A building block, not just a demo

AI that contracts can trust without trusting anyone

Today, when a smart contract wants an AI's opinion, it has to trust someone: an oracle, an API company or a secure server. Chainmind removes that middleman by running the model inside the contract itself.

  • Nobody can fake the answer

    The model runs inside consensus, so a result is as final as a token transfer.

  • Nobody can change the model

    After sealing, the weights are fixed forever and pinned by their SHA-256 hash.

  • Nobody can switch it off

    No company, no API key and no server that can be shut down.

  • Anyone can check it

    The same input and seed give the same output on any machine, bit for bit.

  • Other contracts can call it

    One model on chain becomes a shared library that every app on NEAR can use.

  • It costs cents

    A 48-token story used 194 Tgas on testnet, about 0.02 NEAR at the base gas price.

What one call to generate() does

Inside a single NEAR transaction

The contract is ordinary WebAssembly. Each validator that executes your transaction does all of this, and they all get the same answer.

  1. 1

    Loads the weights

    Reads 298,843 bytes from contract storage: int8 matrices, the tokenizer and position tables.

  2. 2

    Reads your prompt

    Splits it into tokens from a 512-piece vocabulary, the way the model was trained.

  3. 3

    Runs the transformer

    Five layers, eight attention heads, 64 numbers wide. Integer matrix maths keeps it cheap and exact.

  4. 4

    Picks the next token

    Samples from the model's odds using the block's random seed, or yours if you pass one.

  5. 5

    Stops before gas runs out

    Repeats until the story ends or gas gets low, then returns the text and records it on chain.

Determinism

Three machines, one story

Floating-point AI usually gives slightly different answers on different hardware. Chainmind uses integer matrix products, its own exponent function and a fully specified random generator, so the output is reproducible bit for bit.

Laptop · x86-64 native The same engine compiled for a normal computer "The cat" · seed 7 → [269, 261, 272, 314, 310, 382, …] identical, all 32
This page · your browser The same engine as a 72 KB WebAssembly file "The cat" · seed 7 → running… checking…

Anyone can check an onchain story: take the prompt, temperature and seed from the transaction and run chainmind run on your own machine. You get the same tokens. The live testnet contract wrote the same "Tim" story for seed 1 that the printer above prints.

How to use it

Five ways in, from a free question to calling it from your own contract. The commands use NEAR's command-line tool, near-cli-rs.

Free · no account needed

Ask it without a transaction

A read-only call. Nothing is recorded and nobody pays. Up to 48 tokens.

near contract call-function as-read-only mind-mwdofvuu.leston.testnet complete json-args '{"prompt":"The cat","max_tokens":32,"seed":"7"}' network-config testnet now
Recorded forever · about 0.02 NEAR

Ask it in a transaction

Every validator runs the model and the answer is stored with your account as the caller. Leave out the seed to use the block's randomness.

near contract call-function as-transaction mind-mwdofvuu.leston.testnet generate json-args '{"prompt":"Once upon a time","max_tokens":48}' prepaid-gas '300.0 Tgas' attached-deposit '0 NEAR' sign-as YOUR_ACCOUNT.testnet network-config testnet sign-with-legacy-keychain send
Shared · one story for everyone

Write the next chapter

Steer the Endless Story with a few words of your own, or none.

near contract call-function as-transaction mind-mwdofvuu.leston.testnet extend_story json-args '{"nudge":"Then a dragon"}' prepaid-gas '300.0 Tgas' attached-deposit '0 NEAR' sign-as YOUR_ACCOUNT.testnet network-config testnet sign-with-legacy-keychain send
Trust nothing · check it yourself

Re-run any answer locally

Take the prompt, temperature and seed from a transaction. You get the same words the validators wrote.

cargo run -p chainmind-tools --release --bin chainmind -- run models/stories260k.cmnd "Once upon a time" --max 48 --temp 0.8 --seed 1
For developers · Rust

Call it from your own contract

Any NEAR contract can ask Chainmind for text and act on the answer in a callback. The whole transaction shares 300 Tgas, so a call from another contract fits about 50 tokens.

#[ext_contract(ext_mind)]
trait Chainmind {
    fn generate(&mut self, prompt: String, max_tokens: Option<u32>,
                temperature: Option<f32>, seed: Option<U64>) -> Generation;
}

ext_mind::ext("mind-mwdofvuu.leston.testnet".parse().unwrap())
    .with_static_gas(Gas::from_tgas(220))
    .generate("The knight opened the chest and found".into(), Some(40), None, None)
    .then(Self::ext(env::current_account_id())
        .with_static_gas(Gas::from_tgas(10))
        .on_text())

Limits, plainly

How far it scales

This will never run a chatbot like ChatGPT. It's for small models where trust matters more than size: scoring, classifying, deciding and generating game content. Many useful models are that small.

Research

Checking big models on chain

Run a large model off chain and post its answer with a deposit. If someone disputes it, the contract recomputes just the one layer in question. That only works with an engine whose maths matches bit for bit, which is what Chainmind has.

For scale: SmolLM2-135M, one of the smallest models Ollama runs, is about 520 times our model. By our estimate it would lock around 1,350 NEAR of storage and need about ten chained calls per token. That is why big models are better checked on chain than run there.
