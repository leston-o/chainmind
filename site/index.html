Why it exists

Today, a smart contract that wants an AI's opinion has to trust someone. An oracle. An API company. A secure server. Chainmind removes the someone.

Nobody can fake itThe answer is computed in consensus, as final as a token transfer.
Nobody can change itSealed weights, pinned forever by their SHA-256 hash.
Anyone can check itThe same prompt and seed give the same words on any machine.
How it works

One transaction. Five steps. Every validator.

The contract is ordinary WebAssembly. When you call generate, each validator runs all of this, and they all land on the same words.

0 Tgas of 300 Scroll to run a transaction

Real total from testnet: 194.4 Tgas for a 48-token story. The split between steps is approximate.

  1. 01 · ≈16 Tgas

    Load the weights

    The contract reads the sealed model from its own storage: int8 matrices, the tokenizer and position tables.

  2. 02

    Read your prompt

    Your words are split into pieces from a 512-piece vocabulary, exactly how the model was trained.

  3. 03 · ≈3.6 Tgas per token

    Run the transformer

    Five layers, eight attention heads, 64 numbers wide. Integer matrix maths keeps it cheap and exact.

  4. 04

    Pick each next word

    The next token is drawn from the model's odds using the block's random seed, or yours if you pass one.

  5. 05 · 194.4 Tgas total

    Return and record

    The text comes back with the transaction and stays in the chain's history. If gas gets low, it stops early and returns what it has.

Small models inside one call
A 260K-parameter model sealed on testnet, writing up to 70 tokens per transaction with the same output everywhere.

        
Next · in design
One model across shards
Put each layer in its own contract and chain the calls. NEAR is sharded, so the layers can share the work.

        
Research
Checking big models on chain
Run a large model off chain and post its answer with a deposit. In a dispute, the contract recomputes only the layer in question, which needs maths that matches bit for bit.

      

      
For scale: SmolLM2-135M, one of the smallest models Ollama runs, is about 520 times this model. By our estimate it would lock around 1,350 NEAR of storage and need about ten chained calls per token. That's why big models are better checked on chain than run there.
